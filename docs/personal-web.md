# 自用截图账本网页

本版本提供可从手机浏览器打开的独立轻量入口，复用 DecisionJournal 账本格式。它不是原有 React 聊天页面的部署，也没有自动接通其模型或旧微信渠道。

## 启动与访问

在 Mac 上运行仓库里的 `agent/scripts/start_personal_web.sh`。默认只在 `http://127.0.0.1:8910` 监听；手机使用时指定电脑当前局域网 IP，例如 `agent/scripts/start_personal_web.sh --host 192.168.1.10`。不要照抄示例地址。手机与电脑需在同一可信网络，电脑保持运行；客户端隔离或防火墙可能阻止手机连接。本版本使用 HTTP 和访问密钥，不适合公网或不可信 Wi-Fi，没有配置公网隧道。

数据默认保存在 `~/Library/Application Support/VibeTradingPersonal/`，可用 `VIBE_PERSONAL_HOME` 更改。`access-key.txt` 是首次运行生成的随机访问密钥，网页中输入即可登录。密钥不放 URL、不写浏览器本地存储；会话 cookie 为 HttpOnly/SameSite=Strict，服务重启后需重新登录。账户账本和截图不放进 Git 仓库。请备份整个数据目录（服务停止时复制）；本版本还没有自动备份、数据删除 UI 或后台开机自启。

脚本只编译随附 Swift OCR 程序并启动标准库 Python 服务，不安装依赖，不连接券商、模型或微信。Mac 需已有 Swift 编译工具；未能编译时仍可对照原图手工录入。停止运行可在启动终端按 Ctrl+C。

## 日常流程

1. 上传 PNG/JPEG 截图（上限 12 MB），在电脑本地进行 macOS Vision 文字识别。HEIC 暂不支持。
2. 识别文字是草稿，必须对照原图。仅当识别文本符合简单单笔成交模式时，提供“填入候选”按钮。复杂表格、多笔成交或歧义结果需手动填写。候选可能把列顺序理解错误，不能跳过人工确认。
3. 选择成交、持仓快照、事前想法或计划，填写实际发生时间、数量等字段，勾选确认后保存。持仓截图不被推断为成交，局部截图不等于完整账户。可用资金不填即未知。当前快照只记录持股数量和可用资金，不包含证券估值、成本、冻结资金或账户总资产。
4. 成交无需虚构关联意图；没有事前记录时明确标记为 not_recorded。事后补充的理由也有独立记录时间，不等于事前计划。
5. 历史页可回看来源截图，对成交、意图和快照追加更正。原记录保留，若已有更正，须选择最新更正继续修改。计划通过新的计划版本修订。
6. “复盘与提问”生成本地证据摘要，带原记录编号、原始发生时间、记录时间与来源。可以复制问题和证据到已有 Codex 对话。这是人工衔接，还不是网页内大模型聊天；没有自动行情/公告提炼、投资建议或实时账户同步。

## 去重边界

- 同一图片按内容哈希只存一份；同一图片下同样内容、时间的重复提交不重复记账。
- 提供成交编号时，以账户分组＋来源＋成交编号拒绝跨截图重复。请填写成交编号，不能以委托编号代替（一个委托可对应多笔成交）。
- 不同截图但缺失成交编号、改变填写内容或时间、同一图片中完全相同的多笔成交，不能可靠区分。需要人工核查/补成交编号，不能宣称自动完成全部去重。
- 数据只保存至独立 `personal:gtht` 单用户分组。原 Agent 默认使用另一数据目录；现在可通过 VIBE_TRADING_DECISION_JOURNAL_PATH 单独指定共享账本，无需改变整个运行根。使用 docker-compose.personal.yml 已将本机个人账本挂载至原服务。

## 与原助手共享账本

独立网页默认使用8910端口，原助手使用8899端口。使用以下命令挂载同一份账本：

```sh
VIBE_PERSONAL_DATA_DIR="$HOME/Library/Application Support/VibeTradingPersonal" docker compose -f docker-compose.yml -f docker-compose.personal.yml up -d --no-build vibe-trading
```

该override开启现有调度器和渠道自动启动。运行前核对自己已有的定时任务与渠道配置；仓库不包含个人运行任务或微信登录信息。频道启动成功不等于报告送达。

原助手使用`read_current_holdings`读取共享账本，按[持仓关联约定](personal-holdings-task-contract.md)处理数据时间、完整性和来源。独立截图网页本身不调用大模型。
